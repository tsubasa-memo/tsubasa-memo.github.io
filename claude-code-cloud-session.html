Claude Codeのクラウドセッションを使ったら、いつもの仕組みが動かず手間が増えた記録

公開: 2026年10月25日更新: 2026年10月25日

こんにちは、ツバサです。

2026年9月、Claude Codeの「クラウドセッション」で使えるクレジットが配られた。僕のアカウントにも届いた。もらったものは使わないと損だと思って、9月の終わりにこのブログの作業を1回だけクラウドセッションでやってみた。

結論から書くと、僕の使い方では使ったら損だった。いつも手元のPCで動いている仕組みが、クラウドでは何も効いていなかったからだ。作業そのものは終わったが、その後の点検とやり直しに1か月近く手間がかかった。さらに10月の下旬、GitHubから届いたメールで、Claudeに「すべてのリポジトリに書き込める」権限を許可していたことにも気づいた。

この記事は、そのとき何が動かなかったのか、後から何をやり直したのか、GitHubの権限をどう確かめて外したのかの記録だ。クレジットをもらって使ってみた人、これから使おうか迷っている人に読んでもらえるとうれしいです。

Claude Codeのクラウドセッションとは｜配られたクレジットと手元のClaude Codeとの違い

Claude Codeは、ふだんは手元のPCで動かすAIの作業ツールだ。僕はこのブログの記事のHTMLや、サイトマップなどの周辺ファイルの更新を、Claude Codeに指示して進めている（「AIに聞きながらGitHub Pagesでブログを構築した話｜非エンジニアの記録」に流れを書いた）。

クラウドセッションは、そのClaude Codeを手元のPCではなく、Anthropic（Claudeの開発元）が用意したクラウドのPCで動かす使い方だ。ブラウザのclaude.ai/codeやスマホのアプリから頼めて、PCを閉じても作業が進む。

手元で動かす場合との違いを表にした。

項目手元のClaude Codeクラウドセッション
動く場所自分のPCAnthropicが用意したクラウドのPC
頼める場所自分のPC（外から見る機能もある）ブラウザ・スマホのアプリ・デスクトップアプリ
PCを閉じたとき止まる進み続ける
作業するファイル自分のPCにあるファイルGitHubから取ってきたリポジトリ
手元の設定使えるリポジトリに入れたものだけ
GitHub無くても使える基本的に必要

公式ドキュメントの比較表でも、クラウドセッションは「手元の設定は使えず、リポジトリだけ」「GitHubが必要」と整理されている。

CGet started with Claude Code in the cloudcode.claude.com

クラウドセッションで動かなかったいつもの仕組み｜指示ファイル・検査スクリプト・Gitのフック

9月の終わりにクラウドセッションでやったのは、記事どうしのリンクを増やす作業と、いくつかの記事の数字の訂正だ。作業自体は進み、変更は何回かに分けてGitHubに入った。問題は、ふだん手元で当たり前に動いているものが、クラウドでは何も動いていなかったことだ。

手元ではあったもの手元での役目クラウドでどうなったか
Claude Codeへの指示ファイルと作業ルール記事の書き方、更新するファイル、やってはいけないことをClaude Codeに伝える届かなかった。ルールを知らないまま作業した
記事の検査スクリプト体裁・日付・タイトルの食い違いを公開前に見つける届かなかった。その場で簡易な検査を作り直し、いつもの検査は「次に手元で作業するときに通す」で終わった
Gitのフック（コミット前・送信前の検査）公開してはいけないものや、記録の形の違いを見つけて止める動かなかった。コミットに残る情報の一部が、いつもと違う形のまま入った
作業の記録（手元のメモ）何をやったかを次の作業のために残すクラウドから手元のメモには直接書けず、別の経路で書いて中身を照らし合わせた
いつも開けるサイト料金や規約を公式ページで確かめるクラウドの通信の制限で開けないサイトがあり、確かめられないものが残った
PRの本文変更の説明作業したクラウドセッションのURLが載っていた。公開リポジトリなので誰でも見られる状態だった

なぜ動かなかったのかは、公式ドキュメントを読むと分かる。クラウドセッションは、GitHubからリポジトリを新しく取ってきて、その中で動く。そのとき読まれる設定は、リポジトリに入れて（commitして）ある.claude/settings.jsonだけで、自分のPCに置いている個人の設定（~/.claude/settings.json）や、Gitの管理から外している.claude/settings.local.jsonは読まれない。

CSettings files and precedencecode.claude.com

このブログは公開リポジトリで運営しているので、Claude Codeへの指示ファイルや作業用のスクリプトは、公開しないようにGitの管理から外してある。Gitのフックも、もともとリポジトリを取ってきただけでは一緒に運ばれない。手元で大事にしている仕組みほど、クラウドには届かない作りになっていた。

公式ドキュメントにも、手元の設定や道具、環境が要る作業は、手元で動かすか、手元のセッションを外から操作するRemote Controlのほうが向いていると書かれている。僕の作業はまさにそれだった。

後始末で増えた手間｜検査のやり直しとコミットの記録の修正

クラウドセッションでの作業が終わったあと、手元で次のことをやり直した。

やり直したこと理由
いつもの検査スクリプトを全ページに通すクラウドでは簡易な検査しかできていなかった
ルールどおりになっていない箇所を直す指示ファイルとルールが届いていなかった
コミットの記録を直すGitのフックが動かず、記録の一部がいつもと違う形で入っていた
作業の記録を照らし合わせる手元のメモに直接書けなかった
確かめられなかった料金や規約を公式ページで見直すクラウドの通信の制限で開けなかった

1回の作業のために、手元での点検と修正を何回も重ねることになった。気づいた順に直していったので、全部が片づいたのは10月の下旬で、作業から1か月近くたっていた。手元で作業していれば、どれも作業中に検査やフックが止めてくれていたものだ。

PRの本文に載っていたクラウドセッションのURLも、公開リポジトリでは誰でも見られる。少なくとも、作業にクラウドセッションを使ったことは外から分かる。公開リポジトリで使った人は、PRの本文を一度見ておくと安心だと思う。

GitHubに許可していた範囲｜Claude GitHubアプリは全リポジトリに書き込みできた

10月の下旬、GitHubから「Claudeのアプリが権限を更新し、追加のアクセスを求めている」というメールが届いた。そこで初めて、ClaudeのGitHubアプリが自分のアカウントに入ったままだと気づいた。

ブラウザでクラウドセッションを始めると、最初の案内でGitHubとつなぐように求められる。案内は2段階になっている。

  1. GitHubにログインして、Claudeのアクセスを承認する
  2. ClaudeのGitHubアプリをインストールする

公式ドキュメントによると、2つ目のインストールは「Skip」で後回しにできる。承認だけなら、クラウドセッションが読めるのは公開リポジトリだけで、非公開のリポジトリで作業するにはインストールが要る。僕はこのとき、案内のとおり2つとも進めていた。

GitHubの設定画面でアプリの中身を見ると、僕の場合はこうなっていた。

項目内容
対象のリポジトリすべてのリポジトリ（今あるものと、これから作るもの）
読み取りだけコミットの状態、メタデータ
読み取りと書き込みコード、プルリクエスト、Issue、ワークフロー、Actions、チェック、ディスカッション、リポジトリのフック

クラウドセッションはリポジトリのコードを書き換えて送り返すので、書き込みの権限が要るのは分かる。ただ、対象が「すべてのリポジトリ」になっていて、作業に使ったのとは関係のないリポジトリまで含まれる。会社のリポジトリや、人に見せたくないリポジトリが同じアカウントにある人は、範囲を一度確かめたほうがいい。

Claude GitHubアプリの確かめ方と外し方｜UninstallとRevokeの2段階

使い終わったら外しておくことにした。外すには、GitHubの設定で2か所を操作する。アプリを外しただけでは、アカウントへのアクセスの承認が別の欄に残るからだ。

手順GitHubの画面やること
1右上のプロフィール画像 → Settings → Applications → Installed GitHub AppsClaudeの「Configure」を開き、いちばん下の「Uninstall」で外す
2同じApplicationsのAuthorized GitHub AppsClaudeの「Revoke」で承認を取り消す
31と2の画面をもう一度開くどちらにもClaudeが出ていなければ完了
GReviewing and modifying installed GitHub Appsdocs.github.com GReviewing and revoking authorization of GitHub Appsdocs.github.com

途中でパスワードの再入力を求められることがある。設定画面に入るときのGitHubの確認なので、そのまま入れて進めればいい。「すべて取り消す（Revoke all）」は、ほかのアプリの承認まで消えるので押さないようにした。

いつつないだのかは、同じ設定画面の「Security log」で見られる。アプリのインストールと承認、外したことと取り消したことが、日時つきで残っている。

権限の追加を求めるメールが来ても、承認しなければ今の権限のまま変わらない。使っていないなら、承認するより外すほうが早い。

手元のClaude Codeは、GitHubのアプリを外しても今までどおり使える。僕も外したあと、手元での作業はそのまま続けている。

それでもクラウドセッションを使うなら｜空のリポジトリとRemote Control

僕の使い方では損だったが、クラウドセッションが向いている人もいると思う。手元に独自の仕組みを持っていない人や、新しく何かを試したい人だ。使うなら、次のことを先に決めておくと後始末が減る。

決めておくこと理由
新しく作った空のリポジトリで試す既存の作業や、手元の仕組みに頼っているリポジトリを巻き込まない
GitHubアプリのインストールはSkipするか、リポジトリを選んで入れる「すべてのリポジトリ」に書き込める状態を避ける
効かせたい設定は.claude/settings.jsonに入れてcommitするクラウドが読む設定はこれだけ。公開してよい設定に限る
手元の設定が要る作業は、手元で動かす指示ファイル・検査・フックが届かない
外から様子を見たいだけなら、Remote Controlを使う手元のPCで動かしたまま、スマホやブラウザから見たり頼んだりできる
使い終わったら、アプリを外して承認を取り消す使っていないアプリに権限を残さない

GitHubのアカウントを持っていない人は、ブラウザからだとクラウドセッションを始められない。GitHubとつないでいないと、画面にはGitHubのログインボタンしか出ない。手元のファイルをまとめて送る方法もあるが、ターミナルでClaude Codeとgitを使う必要があり、ふだんGitHubを使っていない人には手間が大きい。

ブログをGitHub Pagesで公開している人は、GitHubのアカウントの入口が増えること自体にも気をつけたい。「静的サイトと動的サイトの違い｜セキュリティで静的サイトが有利な理由」で、静的サイトでも残る入口として、GitHubのアカウントとトークンを挙げた。外部のアプリに渡している権限も、その入口の1つだ。

FAQ

Q. クラウドセッションのクレジットは、手元のClaude Codeにも使えますか？

A. 使えません。Anthropicのヘルプでは、クレジットはクラウドセッション専用で、手元のClaude Codeには使えないとされています。

Q. GitHubのアカウントが無くてもクラウドセッションは使えますか？

A. ブラウザからは使えません。クラウドセッションはGitHubのリポジトリを取ってきて作業する仕組みで、GitHubとつないでいないと始められません。手元のリポジトリをターミナルから送る方法はありますが、Claude Codeとgitをターミナルで使う必要があります。

Q. クラウドセッションでも、手元と同じ設定やフックを効かせる方法はありますか？

A. リポジトリにcommitした.claude/settings.jsonは読まれます。個人の設定（~/.claude/settings.json）、Gitの管理から外した.claude/settings.local.json、Gitのフックは届きません。公開リポジトリに入れたくない設定や検査は、クラウドでは効かせられません。

Q. ClaudeのGitHubアプリを外すと、手元のClaude Codeは使えなくなりますか？

A. 使えます。外れるのはクラウドセッションからGitHubへのアクセスで、手元のClaude Codeは自分のPCのファイルとGitを使うので影響しません。

Q. GitHubから「Claudeが追加のアクセスを求めている」というメールが来たら、どうすればいいですか？

A. 承認しなければ今の権限のまま変わりません。クラウドセッションを使っていないなら、承認せずにアプリを外し、承認も取り消しておくと安心です。

Q. アプリを外したのに、まだつながっている表示が残るのはなぜですか？

A. アプリのインストールと、アカウントへのアクセスの承認は別の欄にあります。Installed GitHub Appsで外したあと、Authorized GitHub Appsでも取り消す必要があります。
